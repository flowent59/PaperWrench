# PaperWrench 0.1.0 — first MVP release (proposed)

Prepared for review; no tag, hosted image or GitHub release is published by M13.
Read [installation and upgrade instructions](../deployment.md) before deploying.

The MVP connects Explorer, schemas and Quality to typed transformations, a
read-only paginated Dry Run, explicit Job execution, durable History and linked
rollback of proven writes. Static Collections retain selected document IDs.
Paperless remains the source of truth and REST is the sole integration boundary.

M13 adds a complete guarded Chromium acceptance scenario on Paperless 3.1.2,
100k synthetic target checks, populated M12 backup/upgrade verification, and
installed-wheel deep-route smoke coverage. It fixes compiled asset routing on
nested URLs, complete-origin comparison, accessible names/landmarks and status
badge contrast, excludes local secrets/data from Docker builds, and updates
compatible vulnerable development dependencies and runtime pip.

No new database revision: Alembic head remains `c814b207f001`. Upgrades preserve
existing History; pre-M8 legacy writes remain unproven/manual review. Do not
resume uncertain writes or infer rollback eligibility from current value equality.

Known limits: one process/worker; explicit resume only; no atomic external writer
protection; one rollback Job per original; immediate Inspector edits have no
durable rollback. Preview limits remain 100,000 targets, 128 MiB serialized results,
300 seconds, four retained previews and 30-minute expiry. Measured synthetic
capacity is not a live Paperless throughput promise. API types are hand-written.
Duplicate detection, AI, analytics and dynamic collections remain outside the MVP.

See [verification results and NOT_RUN items](../m13-verification.md) and the
[security/accessibility review](../security.md) for deployment assumptions,
dependency exceptions and remaining risks. Publishing requires a separate approval.
